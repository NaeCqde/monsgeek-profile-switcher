# MonsGeek Profile Switcher

MonsGeek FUN68（RY5088 系）のオンボードプロファイルの切り替えを、キーボードショートカットとして割り当てられる常駐アプリです。切り替えはキーボードのベンダー HID インターフェースへ 64 バイトの Feature Report を送って行います。

## 動作

| OS      | 接続直後                    | そのあと                                                                        |
| ------- | --------------------------- | ------------------------------------------------------------------------------- |
| Windows | `ON_CONNECT_PROFILE` を送る | ホットキー（既定 `Home`）を押すたびに `PROFILE_CHAT` と `PROFILE_GAME` をトグル |
| macOS   | `ON_CONNECT_PROFILE` を送る | 自動では何もしない（`--set-profile` で手動切替）                                |

- キーボードの抜き差しは Windows の通知で即座に検出します。挿し直すたびに
  `ON_CONNECT_PROFILE` から始まります。
- 切り替えは常に即時です。プロファイルを送るとキーボードが押しているキーを離した扱いに
  してしまうため、ホットキーを押した瞬間に何かキーを押していると、そのキーのリピートが
  止まります（下記）。
- 接続直後はインターフェースがまだ開けないことがあるので、`ON_CONNECT_PROFILE` は
  200 ms 間隔で最大 8 回リトライします。

### 切り替えの判定: ホットキー

ユーザーが割り当てた 1 つのキー（既定 `Home`）を押すたびに `PROFILE_CHAT` と
`PROFILE_GAME` をトグルします。キーが押された瞬間に Windows から直接通知が来て
即座に切り替えます（[windows_events.rs](src/windows_events.rs)、キーの指定方法自体の
パースは [hotkey.rs](src/hotkey.rs)）。

キーは `Ctrl+Alt+P` のように修飾キーと組み合わせても構いません。詳しくは
[設定](#設定) を参照してください。切り替えるたびに、フォーカスしているウィンドウが
あるディスプレイの下部に、数秒で消える小さな通知（`Chat (profile 2)` のような表示）が
出ます（[overlay.rs](src/overlay.rs)）。

## プロファイル送信はキーの押しっぱなしを解除する

FUN68 実機で確認した挙動です。**すでに入っているのと同じプロファイルを再送するだけでも、
そのとき押されているキーが離した扱いになります**（設定は何も変わらないのに、全キーの
リピートが止まりました）。キーボード側がプロファイル適用時にキー状態をリセットしている
ためで、こちらから避ける方法はありません。

そのため、**ホットキーを押した瞬間に何かキーを押していると、そのキーのリピートが
止まります。** ホットキーはユーザーが意図して押す操作なので、これは受け入れている
制限とし、待たずにそのまま切り替えています。

## 設定

`.env` に置きます。場所は `--config` で開けます
（Windows: `%APPDATA%\monsgeek-profile-switcher\switcher\.env`、
macOS: `~/Library/Application Support/monsgeek-profile-switcher/switcher/.env`）。

```env
ON_CONNECT_PROFILE=2
PROFILE_CHAT=2
PROFILE_GAME=1
STATUS_PORT=38415
PROFILE_TOGGLE_HOTKEY=Home
```

| 変数                    | 意味                                                                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ON_CONNECT_PROFILE`    | 起動時・接続時に設定するプロファイル（1〜4）                                                                                                                                                                 |
| `PROFILE_CHAT`          | ホットキーでチャット側にしたときのプロファイル                                                                                                                                                               |
| `PROFILE_GAME`          | それ以外（ゲーム中など）                                                                                                                                                                                     |
| `STATUS_PORT`           | 常駐しているかを GUI が確認するための loopback ポート                                                                                                                                                        |
| `PROFILE_TOGGLE_HOTKEY` | `PROFILE_CHAT`/`PROFILE_GAME` をトグルするキー。`Home`・`F13`・`Ctrl+Alt+P` のように、`+` 区切りで修飾キー（`Ctrl`/`Alt`/`Shift`/`Win`）と最後にキー名を書く（[hotkey.rs](src/hotkey.rs) の `parse_hotkey`） |

変更後はデーモンの再起動が必要です（GUI が変更を検出して促します）。

## 状態の確認

デーモンはステータスポートに現在の状態を JSON で出します。

```json
{ "connected": true, "profile": 2, "chat": true, "game": false }
```

`chat`/`game` は現在の `profile` が `PROFILE_CHAT`/`PROFILE_GAME` と一致するかどうかで、
どちらもキーボードの実際のプロファイル番号から毎回計算し直しています。`--set-profile`
などで別のプロファイルにしていれば両方 `false` になります。値が不明なとき（キーボード
未接続や送信失敗）は `profile`・`chat`・`game` がまとめて `null` になります。キーは常に
4 つとも出ます。

引数なしで起動すると開く状態ウィンドウは、**この項目**を出します。

```
Keyboard:  Connected
Profile:   2
Chat:      Yes
```

デーモンが止まっていれば Keyboard が `(daemon not running)`、値が不明な項目は `-` に
なります。

## コマンド

```
monsgeek-profile-switcher                  状態を表示（ダブルクリック時は GUI）
monsgeek-profile-switcher --daemon         常駐処理をフォアグラウンドで実行
monsgeek-profile-switcher --install        インストールしてログイン時起動に登録し、起動
monsgeek-profile-switcher --uninstall      停止してアンインストール
monsgeek-profile-switcher --start/--stop   インストール済みデーモンの起動 / 停止
monsgeek-profile-switcher --config         .env のあるフォルダを開く
monsgeek-profile-switcher --list-hid       見えている MonsGeek の HID インターフェース一覧
monsgeek-profile-switcher --get-profile    現在のプロファイルを読む（1〜4）
monsgeek-profile-switcher --set-profile N  プロファイル N に切り替える（1〜4）
monsgeek-profile-switcher --help           このコマンド一覧を表示
```

インストール先は Windows が
`%LOCALAPPDATA%\Programs\monsgeek-profile-switcher\switcher\`＋
`HKCU\...\CurrentVersion\Run` への登録、macOS が `~/Applications/MonsGeekProfileSwitcher.app`
＋ LaunchAgent です。

## プロトコルの検証状況

実機 FUN68（有線、VID `3151` / PID `5030`）で確認済みです。

- ベンダー設定インターフェース（`usage_page=ffff usage=0002`、インターフェース 2）の検出
- `GET_PROFILE`（`0x84`）で現在のプロファイルを読めること
- `SET_PROFILE`（`0x04`）で実際に切り替わること（`--set-profile 2` → `--get-profile` が `2`）

バイト列とチェックサム、別モデル / 2.4GHz ドングルで合わなくなったときの調べ方は
[docs/PROTOCOL.md](docs/PROTOCOL.md)。

## すでに諦めた方法

いまはホットキー（[設定](#設定)参照）で手動切替する方式ですが、それ以前に自動判定を
2 系統試して、どちらも最終的に断念しています。記録として残します。

### カーソル型：マウスカーソルの表示と IME の状態を見る方法

最初に作った判定です。次の 2 つの情報を OS から読み取り、どちらかが当てはまれば
チャット欄が開いていると判断していました。

- **マウスカーソルの表示状態。** 3D ゲームは通常マウスカーソルを隠しており、
  チャット欄やメニューを開くとカーソルが表示される、という前提です。
- **IME が日本語入力中かどうか。** 他のアプリの IME の状態は本来のぞけませんが、
  Windows の仕組みを使うと、フォアグラウンドのアプリに問い合わせて日本語入力中かどうか
  を教えてもらえます。次の 3 つの条件がすべて揃ったときだけ「日本語入力中」と
  みなしていました。
    - キーボードの入力方式が日本語になっている
    - IME がオンになっている
    - 変換モードが日本語入力向けになっている（一時的な半角英数入力ではない）

**エモートピッカー問題への対処。** Fortnite では次のような堂々巡りが起きていました。

1. 感情表現（エモート）用のキーを押しっぱなしにする
2. 選択画面（ピッカー）が出て、マウスカーソルが表示される
3. カーソルの表示を検知して、チャット用のプロファイルへ切り替えてしまう
4. プロファイルを切り替えるとキーの押しっぱなしが解除される（前述）ため、押していた
   エモートキーが離れた扱いになり、選択画面が閉じる

押しっぱなしにする行為そのものが切り替えを誘発し、その切り替えが押しっぱなしを壊す、
という循環です。これは、キーを押しっぱなしにしている間はプロファイルの切り替えを
少し待ち、そのキーが離れてから送る、という方法で解決していました（キーボードの列挙や
IME の状態確認だけを単独で動かして検証し、原因がプロファイルの送信そのものであることを
確認しています）。ただし、切り替えがホットキーという意図的な操作になったいまはこの
自己矛盾が起きないため、この待つ仕組み自体は削除しています。

**Apex Legends での問題。** 簡単にはチャット欄の開閉を観測できませんでした。
Fortnite ではチャット欄を開くとカーソルが表示されますし、チャット欄を閉じる際に IME が
自動的に日本語から英語に戻るため、開閉を検知しやすかったです。

Apex Legends ではチャット欄を開いてもカーソルは現れず、しかもチャット欄を閉じた後も
IME の日本語状態が維持されるため、この判定方法が使えませんでした。

### キャレット型：画面を撮影してキャレットの点滅を探す方法

IME やカーソルのような OS の情報に頼らず、チャット欄の中で点滅する文字カーソル
（キャレット）を、画面をスクリーンショットのように定期的に撮影して直接見つける方式
です（ゲームのプロセスには一切手を触れません）。おおまかには次のような手順で
判定していました。

1. 画面を一定間隔で撮影し、小さなマス目に分けて明るさと色を記録する。
2. 撮影した画像の中から、チャット欄そのものらしき四角い領域を先に見つける（枠線や、
   周りと違う単色の背景をもとに）。見つからなければ、それ以上の判定は行わない。
3. 見つけたチャット欄の中で、直前の撮影と比べて明るさが変わった部分だけを取り出す。
4. チャット欄の中身がほぼ一斉に変化していたら（ボタンの色が変わったときなど）、その
   撮影は無視する。
5. 変化した部分の形と色を調べ、細くまっすぐで縦長など、本物のキャレットらしい見た目を
   しているものだけを候補として残す。点滅しているかどうかは、直前の撮影と見比べて
   明るさが切り替わっているかで確認する。

**安定させるための工夫。** タイピング中は文字の追加・削除でキャレットの位置が動き続ける
ため、1 回でも見失っただけでプロファイルを戻すと不安定になります。何回か連続で
見つからなかったとき（3 回）だけゲーム側のプロファイルへ戻し、見つかった瞬間は即座に
チャット側のプロファイルへ切り替える、という規則にしていました。

**Fortnite・Genshin Impact ではキャレットが頻繁に動くと検知に失敗することがあり、
Apex Legends では逆に誤検知が次々と発生するなど、最終的に断念しました。** 実際に
キャレットと誤検知されたものの例です。

- スクロールバー（チャット欄の枠を突き抜けて伸びる縦長の帯）
- メールやファイル一覧の行
- 床や壁の模様のノイズ（たまたま形の条件に当てはまってしまう）
- ボタンの背景の色が変わるアニメーション（「一括受取」ボタンなど）
- 装飾のある建物の柱（縦長だが幅が一定でない形）

条件を絞るたびに、それまで検出できていた別の場面を取りこぼす、といういたちごっこが
続きました。

Apex 専用にチャット欄の周辺だけを切り出して調べる方法も試しましたが、その範囲に
写っていた別のものがキャレットとして誤検知されてしまい、使い物になりませんでした。

これと並行して、Apex がチャット欄を開いた瞬間に必ず表示する「発言:」という文字
（英語版は「Say:」）を、Windows 標準の文字認識機能（OCR）で読み取る方式も試しました。
画面全体を認識にかけてもこの文字はほとんど読み取れず（実測 19 回中 0 回）、その部分
だけを切り出して拡大しても、チャット欄の半透明の背景越しに動く景色が見えてしまい、
文字の濃淡がフレームごとに変わって認識が安定しなかったため、これも断念しています。

最終的に、これらの自動判定はいずれも「ゲームによっては信頼できる合図が原理的に
存在しない」という壁に突き当たったため、ユーザーが明示的に押すホットキーに置き換え
ました。
